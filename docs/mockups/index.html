Shipwatch · UI mockups

A tiny native macOS menu bar app (SwiftUI MenuBarExtra, window style) that watches the GitHub repositories you pick: latest release, Actions status with links to running workflows, last activity, open issues, and open PRs with a separate Dependabot count. Read-only access through a GitHub App (device flow sign-in), with the GitHub CLI token as fallback. All data below is fictional.

01 · Menu popoverdark, one row expanded

  1. Menu bar icon shows the worst current state as a dot: yellow = something running, red = something failed.
  2. Summary chips: how many repos are running / failing / passing.
  3. Each row: CI status icon (click opens the running or latest run), repo name (opens repo), latest release tag + age (opens release), open issues, open PRs, Dependabot PRs as a separate clickable segment, last activity.
  4. Click a row to expand it: running and queued workflows with direct links, then the latest result of each workflow on the default branch.

05 · First run & sign-inGitHub App device flow, gh CLI fallback

  1. Sign in with GitHub starts the OAuth device flow of the Shipwatch GitHub App. No client secret ships in the app; the token is stored in the macOS Keychain.
  2. The user types the code on github.com. The app polls until approved (or the code expires).
  3. If the app isn't installed yet, Shipwatch links to the installation page where the user selects repositories. Tokens can only read repos where the app is installed, so access stays limited to what was set up.
  4. Use GitHub CLI token reads gh auth token on demand (never copied to disk by Shipwatch). Shipwatch still only queries the repos configured in Settings.
